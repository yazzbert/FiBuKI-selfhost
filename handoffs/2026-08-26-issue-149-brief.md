# #149: a UI correction leaves no provenance, so re-extraction still discards it

Written 2026-08-26 at the end of the #116 session, at Stefan's direction: #116 is landed and
#149 is the next lane, in its own session. Nothing here is started — this is the whole brief.

## Goal

Make a hand correction made **in the UI** record itself the same way a correction made through
the MCP tool does, so `retry_file_extraction` refuses to overwrite it and
`list_files handCorrected: true` reports the real corrected population.

## Read first

1. Upstream issue **felixtosh/FiBuKI#149**, which states the gap and rules out the wrong fix.
2. `functions/src/files/extractionCorrectionOps.ts` — `buildExtractionCorrection` (line 135 on
   upstream `main`) is the rule that decides what actually moved (cents, a Timestamp date, a
   line-item array) and writes `extractionCorrectedFields` / `extractionCorrectedAt`.
3. `functions/src/tools/handlers.ts` — `updateFileExtraction`, the only production caller of it.
4. `lib/operations/file-ops.ts:610` — `updateFileExtractedFields`, the UI path, which builds its
   own update map and `updateDoc`s straight to Firestore. Called from
   `components/files/file-detail-panel.tsx:380`.
5. `CLAUDE.md` — the Cloud Functions pattern. This is the argument for the fix, not just a
   convention: a direct client write of a business decision is what the pattern forbids.

## The gap

The provenance stamp is written **inside** `buildExtractionCorrection`, and only the MCP tool
routes through it. The file detail panel corrects through `handleUpdateExtractedFields` →
`updateFileExtractedFields`, which never touches it — so it writes no `extractionCorrectedFields`
and no `extractionCorrectedAt`.

Consequence, live on `main` since #147 merged: a correction made by an agent is protected, and a
correction made by a person in the UI is not — and the UI is the common case. The next
`retry_file_extraction`, or any sweep passing `force`, sees no marker, re-rolls the model and
discards a re-keyed total or a corrected rate exactly as before.

## Scope

Two acceptable shapes, both server-side. Pick one and say why in the PR:

- Route the UI path through the same callable the MCP tool uses, or
- Move the write behind a callable that calls `buildExtractionCorrection`.

Whichever: the comparison of what moved stays on the server, in one place, and the UI keeps
whatever it needs for its optimistic update.

## Non-goals

- **Do not duplicate the stamping rule client-side.** That is the fix #149 exists to prevent —
  two copies of "did this field really change" drift, and the drift is silent.
- Do not touch `retry_file_extraction`'s refusal logic or the `HAND_CORRECTED` error. #147
  shipped those and they are correct; they are simply half-covered until this closes.
- Do not widen into the other extraction write paths in `file-ops.ts` unless one of them also
  writes a corrected field. Check, then say what you found.

## Guardrails

- **Upstream is the target.** Branch off `origin/main` (`felixtosh/FiBuKI`), not fork `main` —
  they are far apart. Push the branch to `fork` and open the PR cross-repo; a bare push to
  `origin` is 403 and the fine-grained token cannot create the PR. The classic-token route is in
  memory `reference_fibuki_stacked_pr_ci_carrier`.
- **Concurrent sessions share this checkout.** Commit from an isolated worktree off
  `origin/main`; do not switch the shared checkout's branch. See
  `feedback_concurrent_sessions_on_audit_lxc`.
- **Host safety.** No full `vitest`, no project-wide `tsc`, no `next build` on the audit box.
  Scoped forms only; the full suite is CI's job.
- The tool-definition drift gate must stay green if any tool description changes: regenerate
  `lib/data/generated-tool-definitions.ts` (`functions/lib/tools/definitions.js` must be compiled
  first — a single-file `tsc --ignoreConfig` is enough).
- If the fix is tested through the in-memory Firestore, read memory
  `reference_fibuki_mock_firestore_blind_spots` first, then mutation-check the test: delete the
  line you think it covers and confirm something turns red.

## Interim, for anyone sweeping before this lands

Treat UI-corrected files as **unknown**, not as `handCorrected: false`. The flag under-reports
the corrected population until this closes.
